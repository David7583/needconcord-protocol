# 行为准则 / Code of conduct

讨论应围绕规范、证据与实际影响，尊重参与者的语言、背景与能力。欢迎明确反对和技术反例；禁止人身攻击、骚扰、歧视、威胁、冒充身份、泄露私人信息以及利用维护权限报复。不要把支付、商业关系或组织地位当作发言资格。

Discuss specifications, evidence and practical effects respectfully across languages, backgrounds and abilities. Disagreement and counterexamples are welcome. Personal attacks, harassment, discrimination, threats, impersonation, disclosure of private information and retaliation through maintainer powers are prohibited. Payment, commercial ties and organizational status are not prerequisites for participation.

本准则适用于项目 Issue、PR、讨论和以项目名义开展的活动。维护者可要求修改措辞、隐藏泄露信息、暂停讨论或限制重复违规者参与，并说明与严重程度相称的理由；处理时应尽量保护报告者与受影响者隐私。利益相关维护者应回避处理自己的争议。

This code applies to issues, pull requests, discussions and activities conducted in the project's name. Maintainers may request edits, remove exposed information, pause discussion or restrict repeated misconduct, with proportionate reasons and attention to privacy. Maintainers with a direct conflict should not adjudicate their own dispute.

## 私密举报与处理边界 / Private reporting and limits

NeedConcord Protocol 的初始维护者为 David7583。首期行为举报采用 GitHub 的 **Report abuse / Report content → GitHub Support**：对违反 GitHub 平台规则的骚扰、威胁、泄露隐私等行为，使用相关用户或内容旁的举报入口，或官方说明中的联系表单。举报提交给 GitHub Support，不是公开 Issue，也不是项目维护者收件箱。[GitHub 举报操作说明](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam)

The initial maintainer of NeedConcord Protocol is David7583. For conduct violating GitHub's platform rules, use **Report abuse / Report content → GitHub Support**, or the contact form linked in the official instructions. Reports go to GitHub Support, not a public issue or the project maintainer's inbox. GitHub handles platform reports under its own policies; this project cannot promise anonymity, a response deadline or a particular decision.

**这一替代渠道有范围限制：**项目尚未提供独立私密投诉邮箱；GitHub Support 不负责裁定所有项目内部争议。对于不属于平台违规、但需要私下向维护者说明的问题，可以仅公开询问“需要私密联系途径”，不附当事人身份、指控或证据；在维护者给出并核验可用渠道前保留材料。这个询问本身不是私密报告。不能把 GitHub 用户名当作私信功能，也不能将 [漏洞报告](SECURITY.md) 用作通用行为投诉箱。

**This alternative has limits:** there is no separate confidential project complaints inbox, and GitHub Support does not adjudicate every internal dispute. For other matters requiring private contact, a public request may ask only for a private contact method, without identities, allegations or evidence. Keep sensitive material local until a working channel is provided and verified; the request itself is not a private report. A GitHub username is not a direct-message facility, and vulnerability reporting is not a general conduct inbox.

不要在公开 Issue、PR 或讨论发布他人隐私或指控材料。维护者只能处理实际收到或看到的内容，不能声称已收到提交给 GitHub 的私密报告。后续申诉可由未参与原处理的维护者审查；当前仅一名初始维护者，无法保证独立复核。涉及该维护者的指控若违反平台规则，可直接报告 GitHub；紧迫的现实人身安全问题不应等待项目流程。

Do not publish private information or sensitive allegations in issues, pull requests or discussions. Maintainers can act on material they actually receive or observe; they must not claim receipt of a private GitHub Support report. An uninvolved maintainer may review an appeal, but a single initial maintainer cannot guarantee independent review. Platform violations involving that maintainer may be reported directly to GitHub. Urgent real-world safety concerns should not wait for project processes.
