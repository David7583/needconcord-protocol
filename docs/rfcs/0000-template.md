## 1. 问题与证据 / Problem and evidence

陈述当前规则、真实或明确标注的模拟场景、最小反例及影响。不要仅用实现便利论证改变协议。
State the current rule, real or explicitly synthetic scenario, minimal counterexample and impact. Implementation convenience alone does not justify a protocol change.

## 2. 原则约束 / Principles

检查需求优先、角色中立、表达非承诺、交易状态独立、非交易方案、去中心、免费协议、隐私与证据来源。
Check demand-first design, role neutrality, non-commitment, independent transaction state, non-transactional paths, decentralization, free use, privacy and evidence provenance.

## 3. 规范性提案 / Normative proposal

用 MUST/SHOULD/MAY 给出字段、错误码、状态或运行行为，指定 Schema/单包语义/有状态/传输/治理层。附前后样例。
Define fields, errors, states or behavior using MUST/SHOULD/MAY and assign the responsible layer. Include before/after examples.

## 4. 替代方案与反例 / Alternatives and counterexamples

至少评估保持现状、可选扩展和核心修改；列出每种方案的失败场景，不预设投票最多即正确。
Evaluate no change, optional extension and core amendment, with failure scenarios for each. Popularity is not correctness evidence.

## 5. 兼容与迁移 / Compatibility and migration

旧新生产者/消费者组合、版本标识、迁移数据来源、不可自动转换部分、回退策略与原始数据保留边界。
Old/new producer-consumer combinations, version identifiers, migration provenance, non-automatable transformations, rollback and original-data retention boundaries.

## 6. 安全、隐私与商业边界 / Security, privacy and commercial boundaries

威胁模型、授权真实性、最小披露、重放与拒绝服务、扩展执行风险、计费/承诺边界及剩余风险。
Threat model, authorization authenticity, minimal disclosure, replay/DoS, extension-execution risks, charging/commitment boundaries and residual risks.

## 7. 验证计划与实际结果 / Validation plan and actual results

公开正反向量、序列、失败恢复、独立实现、边界值；分开列计划和已执行结果。指定通过与拒绝条件。
Public positive/negative vectors, sequences, recovery, independent implementations and boundaries. Separate plans from executed results and define acceptance/rejection criteria.

## 8. 决策记录 / Decision record

主要支持/反对意见、未解决问题、维护者理由及日期；投票只作为意见，不自动修改规范。
Material support/objections, unresolved questions, maintainer rationale and date. Votes inform but do not amend the specification automatically.
