# 协议修订与兼容性提案

状态：2026-11-04，本地、可逆、未发布的 `ODIP/0.1.3-exp.1` 候选。来源为发起者指定的 v0.1.2 草案，完整原始资料离线保存；公开包保留本表以及最小兼容性夹具，供独立实现者理解差异。本次未重写协议目标，也未引入支付、中心目录、平台账号或协议税。

选择新实验标识是因为**验证接受集合收紧也属于兼容性变化**。沿用 `ODIP/0.1.2` 会让两个实现对相同包得到相反判断。`0.x` 实验阶段采用单独标识，不意味着稳定 SemVer 补丁版本向后兼容；最终发布版本仍待维护者裁定。

| 变化 | 基线证据 | 候选处理 | 影响与迁移 |
|---|---|---|---|
| 需求消息缺失关联 ID | §2.2 表述需求关联；Schema 未条件必填 | S-02 六种需求关联消息必须有 `intent_id` | 旧缺失消息拒绝；从可信上下文恢复，不能随机制造关联 |
| 跨字段关联不一致 | Schema 无法比较两个字段 | M-01 同包 `target_intent_id` 与封装一致 | 修正错误数据，保留原包审计；不是简单替换版本 |
| UTC 不统一 | §2.2 要求 UTC；date-time 可接受偏移 | S-04 统一大写 T/Z、最多六位小数且有效日期 | 原偏移时间按真实时区转换；保留原始输入，不能仅删偏移 |
| inferred 宣称成交/解决 | §5 禁止；Schema 未阻止 | M-02 独立语义校验；M-03 confirmed 必须有说明 | 降为 unknown/unmet/pending 或补真实确认，不能伪造来源 |
| 未校验 commerce | packet 接受任意扩展 | S-06 内联已知扩展结构；M-04 分账约束 | 畸形已知扩展拒绝；未知非关键扩展继续忽略 |
| 分账分母含糊 | 0.0035=0.002+0.0015 示例 | 候选解释为同 `fee_basis` 的比率，总和不超过总费率 | 如旧实现采用“服务费收入份额”，必须显式换算；语义选择须公开审阅 |
| 收费声明与授权 | `consent_recorded` 仅布尔声明 | M-05 false 是未授权披露，仍可交换，任何值均不自动产生支付权 | 无资金执行；合同授权与单次计费核验未实现 |
| gaps 是否必需 | §2.1 必需列与 §4、Schema 冲突 | 明确可选，应披露已知差距，缺失不等于没有差距 | 保留现有字段接受集合 |
| source.observed_at 是否必需 | §10 正文与 Schema 冲突 | 明确 SHOULD，缺失为未知新鲜度 | 不补造采集时间 |
| 核心可选字段兼容承诺 | §12 与 additionalProperties=false 冲突 | 核心字段集合关闭；仅未知非关键扩展可忽略 | 新核心字段必须新版本，不声称任意可选字段自动兼容 |
| 幂等与冲突 | 演示仅查 ID，未比较内容 | T-02 原始 UTF-8 字节相等；同 ID 异字节冲突 | 重试必须重用原始字节；不是 JSON 语义规范化 |
| 消息状态与授权 | 原规范未定义状态机 | ST-01 至 ST-07 本地严格有序实验配置 | 乱序必须重试；撤回终止该意图；跨组织委托授权仍未定义 |
| 回执错误原因 | reason_code 可选 | S-05 rejected 必须提供非空 code | 旧无原因拒绝包不符合候选 |
| 字段长度 | ID 部分无限长 | 各关联/参与者 ID 至多 128 字符 | 超长 ID 需双方显式映射，不能截断造成碰撞 |
| UUID 大小写 | format uuid 接受大写变体 | 要求小写十六进制标准连字符格式 | 新候选发送前规范化；不得改变已投递消息字节后以同 ID 重试 |

涉及核心字段的名称、含义主体及七种核心消息种类均保留。`fulfillment.quote` 仍是可选能力；商业披露仍非强制。参考实现支持它们，不表示每个 ODIP 核心实现都必须具备商业扩展和履约扩展。

商业分账有两个可选解释：按交易计费基数比率，或按服务费收入份额。推荐前者，因为原样例直接给出可加和费率；本候选仅使这一解释可测试，未执行任何分账，也未替维护者最终裁定商业合同语义。若不能确认，发布时应把 commerce 标记未稳定的可选扩展，不能静默迁移。

本候选不自动导入旧消息。迁移过程 MUST 验证旧版本、校验字段、获得真实关联/来源信息、显式创建候选消息、记录旧新消息映射。不得修改已投递同 ID 原始字节并重试；跨版本迁移应使用新 `message_id`。原始审计包应离线留存且遵守授权与保留期限。

可复核材料为 [公开向量说明](../conformance/README.md)、[manifest](../conformance/manifest.json)、[完整候选规范](../SPEC-zh-CN.md)。这些材料可用于其他语言实现，不依赖参考实现私有数据库结构。
